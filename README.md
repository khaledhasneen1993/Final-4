# Final-4 — Risk v2 / المعاكسة المؤكدة

المدخل المعتمد `cascade_final4_paper.py`، والصنف `Final4PaperHunter`. بوت معاكسة مستقل عن نظام الجزئيات في [Final-3](https://github.com/khaledhasneen1993/Final-3). لم يُعدّل Final الأصلي. هذه المعالجة تتبع التقرير الذي لم يسجّل أي معاكسة ناجحة، وتضيف تأكيدًا أخف وتسجيلًا لأسباب الرفض.

## نظام المعاكسة

| الإعداد | القيمة |
| --- | --- |
| الدخول العادي | شروط الحركة1.2% والحجم3.5× واختلال±0.35 الأصلية |
| المراكز | 3إجمالًا؛ الدخول العادي لا يتجاوز مركزين لترك خانة للمعاكسة |
| عتبة انعكاس الأصلية | خسارة سعرية1.8% |
| تأكيد المعاكسة الجديد | حركة0.6% في الاتجاه المعاكس، حجم1.5×، واختلال دفتر أوامر±0.15 من بيانات حديثة |
| حجم المعاكسة | 45% من القيمة الاسمية لدخول الأصلية |
| تخفيف الأصلية بعد الفتح | محاولة إغلاق50% فورًا |
| وقف الأصلية بعد الفتح | مرشح0.7% من سعر تعبئة المعاكسة، مع الحفاظ على وقف أقرب |
| نجاح المعاكسة | ربح0.7%؛ إغلاق الباقي من الأصلية وترقية المعاكسة |
| مهلة معاكسة جديدة للعملة | أكثر من600ثانية بعد إغلاق مركز نشأ كمعاكسة، حتى بعد ترقيته |
| حد الخسارة المجمعة الإجباري | معطّل؛ حماية6% أدناه تمنع دخولًا عاديًا جديدًا ولا تغلق المراكز جماعيًا |

لا تفتح معاكسة لمجرد بلوغ1.8%: يلزم التأكيد والهامش والسعر الحديث وخانة متاحة. مصدر شموع التأكيد هو المخزن الحي نفسه؛ لا يُنفّذ مسح شموع REST بطيء آخر عند الانعكاس. يُفحص الوقف وعتبة الانعكاس مجددًا قبل التعبئة. لا توجد سلسلة تعزيز أو تكرار معاكسة للأصلية نفسها.

لكل مركز `position_id` مستقل ورمز سوق حقيقي. تحفظ `reversal_stats` عدد المحاولات والفتحات والرفض بسبب غياب الإشارة أو المهلة أو سعة المراكز أو التنفيذ، وتظهر التفاصيل في السجل وJSON. إذا فشل تخفيف الأصلية يُسجّل الفشل وتبقى الكمية الفعلية تحت وقفها المشدود؛ لا يُدّعى أن التخفيف نُفّذ ولا تتكرر المعاكسة.

أولوية الوقف قد تجعل خروج الأصلية `TIGHT_AFTER_REV` بدل `REVERSAL_WIN` عند تحقق الأمرين في الفحص نفسه. لا يضمن ربح المعاكسة تعويض خسارة الأصلية والرسوم.

## حدود هذه النسخة

هذه معالجة تجريبية للمخاطرة والبيانات، وليست استراتيجية مثبتة الربحية. التقرير السابق كشف انقطاعات متكررة وفروق أسعار ورسومًا وخسائر متراكمة؛ لا يحتوي المسار الكامل للأسعار ودفتر الأوامر، لذلك لا يمكن تحويله إلى اختبار رجعي موثوق أو استنتاج أرباح النسخة الجديدة منه. يلزم اختبار ورقي جديد مستقل قبل أي قرار آخر. نجاح اختبارات البرمجة لا يثبت الأداء المالي.

## الحماية المشتركة — Risk v2

| الإعداد | القيمة |
| --- | --- |
| حساب ورقي جديد | 100 USDT |
| هامش الدخول | 5% من الرصيد |
| الرافعة الحسابية | 50×؛ القيمة الاسمية الأساسية نحو250% من الرصيد |
| الوقف الأولي | 2.8% من سعر التعبئة الفعلي |
| انتظار إعادة الدخول بعد الإغلاق الكامل | 300 ثانية لكل عملة |
| منع الدخول عند اختلاف الإشارة والتنفيذ | فرق مطلق أكبر من0.3% |
| عمر سعر التنفيذ | حتى2ثانية، مع رفض توقيت مفقود أو غير صالح |
| حماية تراجع الرصيد | منع الدخول العادي الجديد عند تراجع6% أو أكثر من أعلى رصيد محفوظ؛ لا إغلاق جماعي إجباري |
| مراقبة الخروج | انتظار2ثانية بين الدورات، إضافة لزمن الشبكة عند الاحتياج إليها |

يتابع الحساب المراكز المفتوحة حتى عند منع الدخول. هذه حماية من التراجع في **الرصيد المحقق**، وليست حد خسارة مضمونًا للقيمة الحالية أو للمحفظة. تسجل ذاكرة القمة والمنع في ملف الحالة وتستمر عبر الإيقاف. عند بداية100 USDT، وقف2.8% على دخول عادي يعرّض نحو7 USDT للحركة السعرية قبل الرسوم والفجوات؛ المراكز المعاكسة لها تعرض إضافي.

تستخدم التعبئة الورقية آخر سعر من شمعة WebSocket مقبولة وحديثة عند توفره، وهو المصدر نفسه المستخدم للإشارة. إذا لم يتوفر سعر بث حديث، يُسمح بسعر REST فقط إذا اجتاز فحص2ثانية وحد اختلاف الإشارة للتعبئات الجديدة. `price_source` و`market_timestamp` محفوظان مع التنفيذات. سعر الشمعة ليس عرض شراء/بيع قابلًا للتنفيذ؛ النموذج لا يحسب السبريد أو التمويل أو الانزلاق أو التصفية.

الرمز المتأخر يُمنع وحده دون إسقاط تدفق بقية الرموز. يُعاد الاتصال عند توقف **كل** الرموز أو إغلاق الاتصال؛ فجوة شمعة تستدعي إعادة تجهيز ذلك الرمز منفردًا. تظل المراكز المفتوحة ضمن الرموز المتابعة حتى لو خرجت من أعلى40. يعاد فحص صلاحية دفتر الأوامر بعد انتظار قفل الحساب، وتُرفض نتيجة عمرها أكثر من2ثانية.

## قفل الربح الصافي

المستويات الأساسية: 1%→0.01%، 1.5%→0.5%، 2%→1%، 2.5%→1.5%، 3%→2%، 3.5%→2.5%، 4%→3%. لكن الوقف الفعلي يأخذ **الأقرب من المستوى الأساسي أو نقطة التعادل المحسوبة بعد الرسوم والنتائج الجزئية مع احتياط سعري0.1%**. أول وقف على مركز جديد يكون قرابة+0.20% بدل+0.01% مع رسوم0.05% لكل تنفيذ. إذا لم يسمح السعر بوضع هذا الوقف في الجهة الصحيحة يؤجل القفل؛ لا يوضع وقف متجاوز لحظة حسابه. لا يُبعد وقف سابق أقرب.

قبل تعبئة إغلاق وقف يُعاد فحص أن السعر ما زال متجاوزًا للوقف. ومع ذلك، الفجوات وتوقف البيانات قد ينتجان خسارة عند سبب `PROFIT_LOCK`؛ الاسم ليس ضمان ربح.

## الحسابات القديمة

**لا تُرقّى جلسة Risk v1 ذات مراكز مفتوحة إلى المخاطرة الجديدة تلقائيًا.** يرفض التشغيل ذلك ويطلب ملف حالة جديدًا أو `--fresh`؛ لا تتغير المراكز أو الأرصدة أو الصفقات القديمة. تبقى ملفاتها وتقاريرها محفوظة، وإيقافها لا يغلق مراكزها. الحسابات القديمة المعتمدة الخالية من المراكز يمكن ترقيتها مع نسخة احتياطية دون تصفير الرصيد؛ وقد تبقى ممنوعة من الدخول إذا كان رصيدها دون حد التراجع. لا تُستخدم ملفات استراتيجيات أخرى للاستئناف.

## لوحة Final + Final-3 + Final-4

داخل Ubuntu في Termux، أوقف اللوحة السابقة بـCtrl+C ثم:

```bash
cd /root/Final-4
git pull --ff-only
bash run_dashboard.sh --fresh
```

إذا لم يكن المستودع مثبتًا، استنسخه أولًا عبر `git clone https://github.com/khaledhasneen1993/Final-4.git` من `/root`.

الرابط المحلي http://127.0.0.1:8787. يتطلب Python3.11+ وGit وvenv. يحدّث المشغّل Final وFinal-3 في مجلدات مصادر منفصلة ويستخدم Final-4 الحالي. كل `--fresh` ينشئ ثلاثة حسابات100 USDT بلا صفقات تحت `.runtime/sessions/`، ويحفظ الجلسات السابقة وتقاريرها.

لاستئناف جلسة Risk v2 نفسها شغّل `bash run_dashboard.sh` دون `--fresh`. لتشغيل Final-4 وحده: `bash run_paper.sh --state sessions/final4-risk-v2.json`. المسار غير الموجود يبدأ100؛ المسار نفسه يستأنف. Ctrl+C يحفظ المراكز ولا يغلقها، فتتوقف مراقبتها. لا تستخدم `--reset` للاستئناف.

تعرض اللوحة الحسابات والإعدادات الفعلية وحالة كل رمز والسجل وأسباب رفض المعاكسة. تتوفر CSV للتنفيذات والصفقات وJSON للحالة لكل بوت أو للثلاثة مع اسم البوت. لفتح التقارير دون تشغيل البوتات: `bash run_dashboard.sh --no-autostart`، على جلسة Risk v2 متوافقة. تفاصيل المسارات والتصدير في [دليل اللوحة](dashboard/README-AR.md).

## التحقق

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv-dashboard/bin/python -m unittest discover -s dashboard/tests -v
```

تختبر البيانات الوهمية المخاطرة والأسعار والرسوم والجزئيات والمعاكسة والتأكيد الأخف والمهلة والحفظ وعزل توقف الرموز. يلزم اختبار ورقي جديد للربحية، واتصال هاتفك الفعلي لم يُختبر هنا.

تحديث الهامش من1% إلى5% في Risk v2 يطبّق على الدخولات الجديدة فقط. تُحدّث بيانات الإعدادات مع نسخة احتياطية دون تعديل كمية المراكز الموجودة أو الرصيد أو سجل التنفيذات. مع وقف2.8% ورافعة50×، قد تتجاوز خسارة مركز كامل حد منع الدخول6%؛ هذا الحد لم يتغير ولا يغلق المراكز الأخرى قسرًا.
